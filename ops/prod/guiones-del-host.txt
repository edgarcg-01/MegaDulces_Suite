# `[OPS.ING.2]` Los guiones que corren en el HOST de `md` desde `~/ops/prod`, y cómo llega cada uno.
#
#   <archivo>  <modo>  [<destino>]
#
#   auto  lo instala `instalar-guiones.sh` desde el commit que la API YA sirve, al final de cada despliegue.
#         Nadie lo sube desde una laptop. La copia previa queda en `<archivo>.anterior`.
#   mano  se COMPARA y se avisa si difiere (en el registro y en el latido `instalar_guiones`), pero lo
#         instala una persona: cada uno trae su motivo al lado. `<destino>` es dónde vive la copia
#         instalada (por omisión, `~/ops/prod/<archivo>`).
#
# ⛔ Regla (heredada de `deploy.sh subir_compose`): si un guion de esta lista llama a otro archivo de
# `~/ops/prod`, ese archivo va en la lista. `npm run check:guiones-host` lo comprueba.
#
# Fuera a propósito:
#   · la AGENDA (`crontab.*`): un cron cambiado sin que una persona lo mire es cómo se duplica un
#     carril. La compuerta sí exige que todo guion que la agenda llama esté acá en `auto`.
#   · lo que corre desde el checkout, no desde `~/ops/prod`: `desplegar-ingesta.sh`,
#     `etiqueta-imagen.sh`, `instalar-guiones.sh` mismo.
#   · lo que corre en la máquina de quien lo lanza: `deploy.sh`, `aplicar-migracion.sh`.
